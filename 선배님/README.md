# 선배님 — 20년치 매매 기록 아카이브

네이버 블로그 [pillion21](https://blog.naver.com/pillion21)(필명 알바트로스, 본명 성필규)의 글 **760편**(2006-06-17 ~ 2026-08-24, 117만 자, 이미지 1,069장)을 전량 수집·정리한 것.

이 저장소가 시스템으로 만들려는 것을, 한 사람이 20년간 손으로 해보고 남긴 기록이다. 코드가 아니라 **참조 자료**다.

---

## 저장소 안에서의 취급

`.gitignore`에서 원문 코퍼스를 제외했다. 타인 저작물이고, 358MB이며, 스크립트로 재수집 가능하기 때문이다.

| 경로 | git | 이유 |
|---|---|---|
| `아카이브/` (760편 MD) | 무시 | 타인 저작물 · 재수집 가능 |
| `이미지/` (1,069장 · 201MB) | 무시 | 바이너리 · 재수집 가능 |
| `_수집원본/` (원본 HTML·데이터·2.8MB js) | 무시 | 중간 산출물 · 재생성 가능 |
| `_수집스크립트/` | **커밋** | 재수집 도구 |
| `*정리.md`, `결손목록.md`, `인덱스.csv` | **커밋** | 내가 만든 산출물 |
| `대시보드.html`, `정리.html`, `내생각.html` | **커밋** | 뷰어 (아래 주의) |

> **주의**: 새로 clone하면 `아카이브.html`은 빈 화면이다. `_수집원본/dashboard-data.js`가 무시 대상이기 때문. 아래 재생성 절차를 밟아야 한다. `투자철학.html`과 `내생각.html`은 자체 완결이라 그대로 열린다.

## 재생성

Claude는 naver.com에 접근할 수 없다(네트워크·프록시·크롬확장 전부 차단). 수집은 **이 PC에서 직접 실행**한다.

```
_수집스크립트\업데이트.bat        새 글만 확인·수집 (없으면 몇 초)   ← 평소엔 이것
_수집스크립트\수집시작.bat        전량 재수집 (수십 분)
_수집스크립트\보완수집시작.bat     누락 미디어 재시도
```

새 글 확인은 예약 작업 **`SeniorBlogUpdate`** 가 매일 07:00 에 대신 한다(`_수집스크립트\schedule.ps1` 로 등록,
`auto_update.ps1` 실행). 새 글이 있으면 수집 → 파생물 재생성 → `인덱스.csv`·`내생각.html` 을 origin/main 에
커밋·푸시까지 한다. 위 bat 은 손으로 돌릴 때만. 자세한 것은 `_수집스크립트\사용법.md` "자동 수집".

수집이 끝나면 파생물 재생성:

```bat
python _수집스크립트\rebuild.py    :: 인덱스·데이터·HTML 3종 일괄 재생성
python _수집스크립트\build_all.py  :: HTML 3종만 다시 만들 때
```

`대시보드.html`은 `_수집스크립트\dashboard_template.html` + `_수집원본\dashboard-data.js`로 만든다. 자세한 절차는 `_수집스크립트\사용법.md`.

## 이 저장소의 어디와 이어지는가

정리 문서에서 뽑은 것 중, 이 프로젝트가 실제로 다루는 문제와 직접 맞물리는 지점.

| 아카이브의 발견 | 저장소의 대응부 |
|---|---|
| **자산 고점 대비 -20% 전 계좌 이탈선.** 20년간 안 바뀐 유일한 숫자. 실제 최대 손실은 -18%, 단 한 번 | `system-trading/` 리스크 파라미터 · 킬스위치 |
| **감내 가능 손실 × 2 = 기대수익이어야 한다.** 손실의 아픔은 같은 금액 수익의 2배라는 전제에서 레버리지를 역산 | `backtest-lab/compound/` · 켈리 비중 산정 |
| **승률 50% 미만으로 수익.** 2023년 주식 17승 21패. 수익률은 낮추고 수익 금액을 키우는 구조 | `backtest-lab/asym/` (비대칭 손익) |
| **"과거 통계는 반드시 깨진다."** 100개 중 5개만 과거 모습을 유지하고 그것도 결국 이탈. 대응은 성배 1개가 아니라 "그만그만한 것 여러 개" | `backtest-lab/stress/`, `compound/robust.mjs` |
| **1승 37패.** 목표치 달성 후 레버리지 50% 증액한 **바로 그날부터** 8개월 수익의 90%를 두 달에 반납 | 복리 증액 규칙의 실패 사례. `compound/` 증액 트리거 설계 시 반례로 |
| **복기가 재기의 방법이었다.** 2009년 '차화정'을 가장 먼저 듣고도 못 움직인 것을 수년간 복기한 결과가 2020년 전환 | `re_sys/` (복기 시스템) |
| **개별 시스템 성능 30 : 운용·자금관리 70.** 금액이 커질수록 시스템 비중이 90%→30%로 떨어진다 | 백테스트 성능 최적화보다 자금관리 우선순위 |

**단, 그대로 이식하면 안 되는 것**이 `투자철학정리.md` 5장에 있다. 특히 레버리지 부분 — 그의 레버리지 관리는 성공한 게 아니라 정지선 덕분에 파산까지 안 간 것이다(파산 3회 · 주문사고 69.7억 · 1승 37패가 같은 사람의 기록이다). 정지선·투입금 산정을 먼저 코드로 박기 전에는 증액 로직을 건드리지 않는 게 맞다.

## 공개 페이지 (`/blog`)

앱이 `trade.habitree.io/blog` 에서 정리 문서 3종(`투자철학정리.md`·`게시판별정리.md`·`종목테마별정리.md`)과 내 생각 노트를 **로그인 없이** 보여 준다. 노트 편집은 관리자 계정만.

| 것 | 정본 | 고치는 법 |
|---|---|---|
| 정리 문서 | 이 폴더의 마크다운 | 파일을 고치고 커밋 |
| 글 색인 | `인덱스.csv` | 예약 작업 `SeniorBlogUpdate` 가 매일 재수집·커밋 (손으로는 `업데이트.bat` → `rebuild.py` → 커밋) |
| **내 생각 노트** | **Supabase `senior_notes` 표** | `/blog` 에서 관리자로 로그인해 쓴다 |
| 시세 대조 차트 | `차트/*.json` 스펙 + 생성된 `.html`·CSV | 스펙을 쓰고 `make_chart.py` 로 만든 뒤 커밋. `/blog` 목록·`/blog/charts/` 가 그대로 서빙한다 |

`내생각.html` 은 이제 정본이 아니다 — 오프라인 뷰어로만 남는다. `_수집원본/notes-data.json` 에 있던 옛 노트는 `npm run seed:senior-notes` 로 한 번 옮겼다(다시 돌려도 같은 글·같은 인용은 건너뛴다). 본문·이미지·대시보드는 공개 페이지에 올리지 않는다.
