# 선배님 블로그(pillion21) 수집·아카이빙 — 사용법

## ★ 가장 쉬운 방법: `수집시작.bat` 더블클릭

그게 전부입니다. 검은 창이 뜨고 자동으로 전부 수집합니다.
창은 그대로 두시면 되고, 다 끝나면 `COMPLETE` 라고 뜹니다.

수집 중 진행 상황은 `선배님\_수집원본\진행로그.txt` 에 실시간으로 쌓이므로,
Claude가 그 파일을 읽어 진행률을 확인할 수 있습니다. (연결된 폴더라 바로 보입니다)

**결과가 저장되는 곳** — 전부 `C:\Dev\trading\선배님` 폴더 안에 자동 생성:

```
선배님/
├─ 아카이브/01_<게시판명>/2024-03-11_글제목.md   ← 본문 전문 + 원문URL + 이미지 + 링크
├─ 이미지/<게시판명>/2024-03-11_<글번호>_01.jpg  ← 이미지 실물 파일
└─ _수집원본/
     ├─ 원본html/<글번호>.html   ← 원본 HTML 통째로 보존
     ├─ 게시판.json              ← 게시판 트리
     ├─ 인덱스.json              ← 전체 색인
     └─ 진행로그.txt             ← 실시간 진행 로그
```

**원칙 1.** 블로그의 원래 게시판(카테고리) 이름과 구조를 그대로 유지해 폴더를 나눕니다.
**원칙 2.** 데이터를 최대한 많이 남깁니다 — 본문 전문 + 원본 HTML + 이미지 실물 + 링크 + 태그.

## 왜 이 방식인가 (검증 결과)

Claude가 네이버에 직접 접근할 수 있는 경로가 하나도 없습니다.

| 경로 | 결과 |
|---|---|
| 클라우드 컨테이너 curl | 연결 실패 (HTTP 000) |
| 로컬 셸(device_bash) | 네트워크 전면 차단 |
| WebFetch 프록시 | HTTP 403 거부 |
| Claude in Chrome 확장 | naver.com 도메인 전체 안전 차단 |
| 컴퓨터 유즈 → Chrome | **read 등급** — 화면만 보임, 클릭·입력 불가 |
| 컴퓨터 유즈 → PowerShell | **click 등급** — 클릭만 가능, 타이핑·붙여넣기 불가 |

브라우저와 터미널은 플랫폼 정책상 Claude가 조작할 수 없습니다.
그래서 **사용자 PC에서 직접 도는 스크립트**를 만들어 폴더에 넣어두는 방식을 씁니다.
사용자 PC는 네이버에 정상 접속되므로, 더블클릭 한 번이면 나머지는 전부 자동입니다.

## 문제가 생기면

**창이 바로 닫힌다 / 빨간 글씨가 뜬다**
→ `_수집원본\진행로그.txt` 를 열어 마지막 줄을 Claude에게 알려주세요.

**보안 경고가 뜬다**
→ 내려받지 않고 만든 배치 파일이라도 SmartScreen이 물을 수 있습니다. 실행을 허용해 주세요.
   스크립트 내용은 `collect.ps1` 에 전부 열려 있으니 직접 확인 가능합니다.

**중간에 멈췄다**
→ 그냥 `수집시작.bat` 을 다시 더블클릭하세요. 이미 받은 이미지는 건너뛰고 이어서 받습니다.

**너무 느리다 / 차단되는 것 같다**
→ `collect.ps1` 의 `Start-Sleep -Milliseconds 160` 값을 400~600으로 올려 재실행.

## 브라우저 콘솔 방식 (대안, 예전 방법)

`.bat` 이 회사 정책 등으로 막혀 있다면 브라우저 콘솔 방식도 그대로 쓸 수 있습니다.
`1_점검.js` → `2_전량수집.js` → `3_이미지수집.js` 순서로 크롬 F12 콘솔에 붙여넣으면
JSON과 이미지 ZIP이 다운로드 폴더에 떨어집니다. 그 파일들을 선배님 폴더에 넣어주시면 됩니다.
(이 경우 `allow pasting` 입력 + "여러 파일 다운로드 허용" 필요)

## 새 글만 받기 (증분 업데이트)

전량 재수집은 수십 분 걸립니다. 새 글만 확인·수집하려면:

```
_수집스크립트\업데이트.bat   더블클릭 (새 글 없으면 몇 초)
```

동작 방식 — 게시판마다 최신 페이지부터 훑다가 **이미 아는 글이 나오면 그 게시판은 중단**합니다. 새 글이 없으면 `NO NEW POSTS`를 띄우고 끝납니다. 새 글이 있으면 본문·이미지를 받아 기존 아카이브에 **덧붙이고**(기존 파일은 건드리지 않음) `_수집원본\신규글.json`과 `증분로그.txt`를 남깁니다.

수집이 끝나면 파생물을 다시 만듭니다:

```
python _수집스크립트\rebuild.py
```

`인덱스.csv` · `dashboard-data.js` · `대시보드.html` · `정리.html` · `내생각.html` 을 한 번에 갱신합니다.
정리 문서(`투자철학정리.md` 등)는 새 글을 읽고 판단해야 하므로 자동 갱신 대상이 아닙니다 — Claude에게 알려주세요.

## 자동 수집 (예약 작업 `SeniorBlogUpdate`)

위 두 단계(업데이트.bat → rebuild.py)를 **매일 07:00 에 예약 작업이 대신** 합니다. 그 시각에 PC 가 꺼져 있거나
로그인 전이면 다음에 켜졌을 때 바로 실행됩니다. 배터리 상태여도 돕니다.

```
_수집스크립트\schedule.ps1              등록 (한 번만. 시각을 바꾸려면 -At '08:30')
_수집스크립트\schedule.ps1 -Remove      해제
_수집스크립트\auto_update.ps1 -DryRun   손으로 점검 — 커밋 객체까지 만들고 푸시는 --dry-run
```
(전부 `powershell -NoProfile -ExecutionPolicy Bypass -File …` 로 실행)

`auto_update.ps1` 이 하는 일:

1. `update.ps1 -Unattended` — 새 글 수집. 엔터 대기 없이 끝납니다.
2. `rebuild.py` — 파생물 재생성. 새 글이 없어도 돌립니다(지난 실행에서 푸시가 실패했으면 이번에 다시 올라가도록).
3. 새 글로 내용이 바뀌는 산출물 2개(`인덱스.csv` · `내생각.html`)를 **origin/main 위에 직접 커밋해 푸시**합니다.
   커밋 메시지에 새 글 제목이 들어갑니다. 푸시되면 공개 페이지(`/blog`)가 배포와 함께 새 색인을 읽습니다.
   - 사용자의 작업 트리·브랜치·미푸시 커밋은 건드리지 않습니다(임시 인덱스 + `commit-tree`).
   - 로컬 main 이 origin/main 과 같을 때만 fast-forward 로 따라갑니다. 미푸시 커밋이 있으면 산출물 2개가
     작업 트리에 수정 상태로 남습니다(내용은 origin 과 같음) → 다음에 `git pull --rebase --autostash`.
   - 푸시 자격은 gh 키링의 `habitree-ai` 토큰을 그 프로세스 안에서만 씁니다. 활성 gh 계정은 바꾸지 않습니다.
   - `아카이브.html`(데이터를 외부 js 로 읽음) · `투자철학.html`(정리 문서만 담음)은 글이 늘어도 안 바뀌므로 커밋 대상이 아닙니다.

확인:

```
Get-ScheduledTaskInfo SeniorBlogUpdate     LastTaskResult 0 = 정상, 1 = 실패
_수집원본\자동수집로그.txt                  실행마다 결과 요약 (수집 상세는 증분로그.txt)
Start-ScheduledTask SeniorBlogUpdate       지금 바로 한 번
```

자동이 아닌 것 — 정리 문서 3종은 그대로 사람(또는 senior-blog 에이전트)이 고칩니다. 새 글이 들어왔는지는
`git log --oneline -- 선배님/인덱스.csv` 또는 자동수집로그로 봅니다.

## 시세 대조 차트 만들기 (`make_chart.py`)

글이 말하는 매매를 시세로 되짚어 보는 인터랙티브 차트 페이지입니다. `차트/<이름>.json` 스펙 하나를 쓰고

```
python _수집스크립트\make_chart.py 차트\2025-04-09_나스닥선물.json
```

을 돌리면 같은 이름의 `.html`(봉 데이터 내장)과 CSV 가 생깁니다. `--all` 을 주면 `차트/*.json` 전부를 다시 만듭니다.
시세는 Yahoo Finance 에서 받으므로 이 PC 에서 실행합니다. 거래소 시간대·통화는 야후 meta 로 따라갑니다 — 미국물은
KST 와 ET 를 같이, 국내물은 KST 만 보이고, `price_decimals: 0` 이면 원화처럼 소수 없이 찍습니다. 스펙 필드 목록은
스크립트 머리 주석에 있습니다.

**페이지 기능은 `chart_app.js` + `chart_css.txt` 한 벌**입니다. 모든 차트 페이지가 같은 앱을 인라인하므로 기능을
고치면 `--all` 로 재생성합니다. 지금 들어 있는 것:

- 시간대 버튼 15분·1시간·4시간·일봉·주봉 — 야후가 주는 것만 뜹니다(15분봉은 최근 60일, 1시간봉은 730일).
  4시간봉은 1시간봉을 UTC 4시간 단위로, 주봉은 일봉을 월요일 시작 주로 페이지가 합성합니다.
- 지표 ▾ 패널 — 이동평균 추가/삭제(SMA·EMA, 기간, 색), 볼린저 밴드(기간·승수), RSI(기간), 거래량, 변동성 지수.
  지표는 페이지가 계산하니 바꿔도 재생성이 필요 없고, 바꾼 설정은 그 브라우저에 남습니다. 스펙 `indicators` 가 기본값.
- 이벤트 마커 — `kind` 가 `entry`(▲ 진입) · `exit`(▼ 정리) · `info`(● 정보). `price` 를 주면 가격선이 같이 그려지고,
  `zones` 는 구간 음영, `lines` 는 가격선. 목록을 누르면 그 자리로 가고, 차트의 마커 봉을 누르면 목록이 밝아집니다.
  `primary: true` 인 이벤트가 "이벤트로 이동"의 기본 자리(없으면 event_date 의 첫 이벤트).
- 십자선 범례(시각 KST/현지·OHLC·등락·거래량·켜진 지표 값), 로그 스케일, 전체화면, 테마.
- 그리기 툴바 — 추세선(두 점)·수평선·수직선·사각형(두 점)·텍스트(클릭 뒤 입력, Enter). 커서 모드에서 그림을
  누르면 선택되고, 끌어서 옮기거나 끝점을 잡아 고칩니다. 색 선택은 새 그림과 선택한 그림에 적용. 그림은
  시간(UTC)·가격에 고정돼 시간대를 바꿔도 같은 자리에 있고, 이 브라우저에 남습니다(`sbchart:draw:<이름>`).
  단축키 — Alt+R 화면 초기화(이벤트로 이동 + 가격축 자동), Alt+T 추세선, Alt+H 수평선, Alt+V 수직선, Esc 취소,
  Delete 선택 삭제, Ctrl+Z 되돌리기. 스펙 `drawings` 로 기본 그림을 둘 수 있고 "기본 그림" 버튼이 그것으로 되돌립니다.
- 표·CSV 의 지표 열은 MA20/50/200·RSI14·ATR14 고정입니다(파이썬이 계산).

- `hourly`·`minutes15` 를 빼면 사건일 기준으로 자동 시도합니다(한도 밖이면 없음). `view` 로 시간대별 "이벤트로 이동" 범위.
- `vol_index` + `options` 를 주면 변동성 지수 창(예: VXN)과 옵션 이론가 요약 표가 붙고, **옵션 자료 페이지
  `<이름>_옵션.html`** 이 따로 생깁니다 — 변동성 지수를 캔들로 보는 차트(같은 앱, 같은 이벤트 마커), 스트래들 % 추이
  (차월·근월·주간), 이론가 표 전체(일봉·1시간봉), CSV. 차트 페이지·정리 문서·`/blog` 카드·노트 페이지가 새 탭으로 잇습니다.
  이론가는 그 지수를 변동성으로 넣은 Black-76 값이며 실제 호가가 아닙니다(`options.notes` 의 전제가 페이지에 같이 보입니다).
- 정리 문서에는 `[제목](차트/이름.html)` 링크로 겁니다 — 변환기가 HTML 태그를 이스케이프해 iframe 은 안 됩니다.
  로컬 뷰어(`투자철학.html`)는 폴더 상대 경로로 열고, 공개 페이지(`/blog`)는 `markdown.ts` 가 그 링크를
  `/blog/charts/이름.html` 로 바꿔 route 가 같은 파일을 서빙합니다. `/blog` 첫 화면의 "시세 대조 차트" 목록과
  내 생각 노트 페이지의 "이 글의 시세 대조 차트"는 `차트/*.json` 스펙의 `post.url` 로 글과 잇습니다 — 스펙만 두면
  목록과 노트에 오릅니다. 산출물(html·csv·json)은 커밋 대상입니다.
