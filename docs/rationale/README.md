# 매매 근거 정리 기준 — 자동매매 적용을 위한 플랫폼 (정본)

`/order` 근거 게이트·거래 폼·`/review` 의 근거 관련 칸은 이 문서의 층 구조를 따른다. 자동매매로 옮길
규칙을 고를 때 **여기 기준을 먼저 고치고** 코드를 따라 맞춘다. 근거 원문은 전부 Supabase `trades` 에 있다.

## 0. 한 줄 요약

근거는 **5개 층**으로 적는다. 층마다 "누가 판정하는가"(사람 / 기계)를 붙이고, 기계가 판정할 수 있는 층부터
자동매매로 옮긴다. 사람만 판정할 수 있는 층(파동 위치)은 자동매매에서도 **사람이 입력하는 값**으로 남는다.

## 1. 왜 층으로 나누는가

| 현황 (2026-09-06) | 값 |
|---|---|
| 거래 | 38건 (100$ TEST 36 · 260905_108$ 2) |
| 근거(`rationale`) 있음 | 4건 |
| 기준(`setup`) 있음 | 0건 |
| 장기추세(`trend`) 있음 | 0건 (REQ-0045 로 신설) |
| 손절·목표 숫자가 있는 근거 | 1건 (260905 #1) |

근거 4건은 전부 파동 카운트·구조 판단이 자유 텍스트로 적혀 있다. "장기적 상승구간으로 … B상승 판단"과
"5파종결 하락"은 같은 파동 언어를 쓰지만 문자열이 달라 `/review` 근거별 표에서 묶이지 않는다. 특히
**장기 국면 판단**이 문장 안에 묻혀 있어, 역추세 진입(장기 상승 판단 + 숏)을 사후에 걸러낼 수 없다.
층으로 나누면 ① 같은 판단이 같은 값으로 묶이고 ② 기계가 대신할 수 있는 층이 드러난다.

## 2. 근거의 5층 (플랫폼 형식)

| 층 | 묻는 것 | 앱의 칸 | 값 | 판정자 | 자동화 등급 |
|---|---|---|---|---|---|
| **L0 장기추세** | 중장기 국면은 무엇인가 | `trades.trend` | 상승추세 / 하락추세 / 기간조정 | 사람 (기계 대체 후보 있음) | B |
| **L1 구조** | 그 국면 안에서 지금 어디인가 | `trades.setup` 칩 | §4 표준 어휘 | 사람 | C |
| **L2 트리거** | 왜 **지금 여기서** 들어가는가 | `trades.rationale` 첫 줄 | §5 트리거 어휘 | 사람 → 기계 | A~C |
| **L3 보조** | 다른 창·다른 종목·수급에서 본 것 | `trades.rationale` 둘째 줄~ | 자유 문장 | 혼합 | B~C |
| **L4 무효화·목표** | 어디서 틀렸다고 볼 것인가, 어디까지 | `stop_price` · `tp1~3_price` · `tp1~3_pct` | 숫자 | 기계 | A |

자동화 등급: **A** 가격·시각·봉 수로 정의되어 기계가 판정 · **B** 기계가 후보를 내고 사람이 확정 ·
**C** 사람 판단만 (자동매매에서는 입력 파라미터로 남김).

## 3. 장기추세 판정 기준 (L0)

사람이 고르는 기준 — **주봉·일봉 기준 고점·저점 갱신 방향**으로 본다.

| 값 | 저장값 | 뜻 |
|---|---|---|
| 상승추세 | `up` | 고점·저점이 함께 높아진다. 조정은 직전 저점을 깨지 않는다 |
| 하락추세 | `down` | 고점·저점이 함께 낮아진다. 반등은 직전 고점을 넘지 못한다 |
| 기간조정 | `range` | 고점·저점 갱신이 멈추고 가격이 구간 안에서 시간을 보낸다 |

기계 대체 후보 (REQ-0027 에서 고정한 국면 렌즈를 3분류로 편 것): BTC 1D 종가 vs SMA200,
밴드 ±3% — 위로 이탈 → 상승, 아래로 이탈 → 하락, 밴드 안 → 기간조정. 사람 판단과 기계 판단이 갈리는
거래가 쌓이면 어느 쪽이 맞았는지 `/review` 로 비교한다. 참고: BTC 국면은 2026-08-21 상승 전환(REQ-0027).

**방향 규칙.** 추세와 반대 방향 진입은 "역추세"로 표시한다 (상승추세 + 숏, 하락추세 + 롱).
자동매매 1단계에서는 역추세를 **금지**한다 — 등록된 근거 중 역추세 1건(260905 #2)이 손절 없이 들어갔다.
기간조정에서는 방향 제한 없이 구간 상·하단 트리거만 허용한다.

## 4. 기준(셋업) 표준 어휘 (L1)

근거 4건에서 뽑았다. 칩은 **구조 + 방향**을 한 덩어리로, 같은 말로 적는다 — 거래에 저장하는 순간 다음 거래의
칩이 된다(`listFieldSuggestions`). 새 구조가 나오면 여기에 먼저 추가한다.

| 칩 | 뜻 | 방향 | 나온 거래 |
|---|---|---|---|
| `임펄스 5파 진행` | 4파 조정이 끝나고 마지막 상승파가 남았다고 판단 | 롱 | 100$ TEST #1 |
| `5파 종결 → 조정 C` | 임펄스 종결, ABC 조정의 B 반등이 끝나고 C 하락 | 숏 | 100$ TEST #3 |
| `조정 B파 반등` | 5파 종결 후 중기 하락 속 B 반등 시작 | 롱 | 260905 #1 |
| `B파 종결 → C파` | B 고점이 직전 고점을 넘지 못하고 꺾임 | 숏 | 260905 #2 |
| `매물대 돌파실패` | 특정 가격대 돌파 실패 후 되돌림 | 양방향 | 100$ TEST #3 (보조) |
| `장기 패턴(컵앤핸들)` | 장기 차트의 패턴 완성 구간 | 롱 | 260905 #1 (보조) |

## 5. 트리거 어휘 (L2) 와 기계 정의

| 트리거 | 사람의 말 (원문) | 기계 정의 초안 | 등급 |
|---|---|---|---|
| 직전 고점 돌파 실패 | "이전 고점을 빠르게 돌파해야하는데 돌파하지못함" | 반등 시작 후 N봉(예: 4h 6봉) 안에 직전 스윙 고점 미돌파 + 종가가 반등 고점 아래 | A |
| 매물대 도달 + 시각 마감 | "79000 매물대 … 10시 이전 해당구간 돌파 실패시" | 가격대 도달 후 지정 시각까지 종가 미돌파 | A |
| 타 종목 저항 대조 | "ETH 차트와 비교했을때 저항부근" | ETH 가 직전 스윙 고점 대비 x% 안에 있을 때 | B |
| 짧은 기간조정 후 재개 | "상승이후 짧은기간조정" | N봉 횡보(폭 < y%) 뒤 횡보 고점 돌파 — N·y 미정 | B |
| 지지 돌파 실패 시 스위칭 | "지지구간 돌파실패시 한번더 상승가능성" | 손절 체결 = 반대 방향 트리거 (무효화 → 진입) | A |
| 수급·이슈 | "바이백이슈로인한 유동성공급 수급" | 기계 판정 불가 | C |
| 급락 추격 | "급락으로 추격진입" | **근거가 아니라 행동.** 금지 규칙(원칙)으로 옮긴다 | 금지 |

## 6. 등록된 근거별 정리

거래마다 원문 → 층별 분해 → 판정. L0 값은 원문 문장에서 읽은 **추정**이며 DB 는 비어 있다(§9).

### 6.1 100$ TEST #1 · 롱 BTC · 8/24 18:58 → 8/25 09:50 · 승

> 마지막 한파동 상승 관점 / 5파 남았다 판단 / 상승이후 짧은기간조정 / 바이백이슈로인한 유동성공급 수급

| 층 | 값 | 등급 |
|---|---|---|
| L0 | (미기재) — 문장상 **상승추세** | — |
| L1 | `임펄스 5파 진행` | C |
| L2 | 짧은 기간조정 후 재개 — N·y 정의 없음 | B |
| L3 | 바이백 수급 | C |
| L4 | 손절·목표 **없음** | — |

판정: 결과는 승이지만 L4 가 없어 자동매매 후보가 아니다. 자동 원칙 1(스탑로스 없이 매매하지 않는다) 위반.

### 6.2 100$ TEST #3 · 숏 BTC · 8/25 09:06 → 13:35 · 패

> 5파종결 하락 / 첨병진입 b반등 완료후 추가진입 / 급락으로 추격진입 / 79000 매물대 쉽게 진입가능성 10시 이전
> 해당구간 돌파 실패시 / 롱스위칭 지지구간 돌파실패시 한번더 상승가능성

| 층 | 값 | 등급 |
|---|---|---|
| L0 | (미기재) — 문장상 **하락 전환** 판단 | — |
| L1 | `5파 종결 → 조정 C` (첨병 진입 뒤 B 반등 완료 후 추가) | C |
| L2 | **두 개가 섞임** — 매물대 79,000 돌파 실패(10시 이전) + 급락 추격 | A + 금지 |
| L3 | 무효화 시나리오가 적혀 있다 — 지지 돌파 실패 시 롱 스위칭 | A |
| L4 | 손절·목표 **없음** | — |

판정: "매물대 돌파 실패 → 숏"은 기계화 가능한 트리거지만 실제 진입은 급락 추격이었다. 같은 날 #5 복기가
그 손실을 "욕심에 의한 추격진입 … 손절 라인이 턱끝까지"로 적었다. 트리거와 행동을 갈라 적어야 통계가 산다.

### 6.3 260905_108$ #1 · 롱 BTC · 9/5 14:44 → 9/6 04:22 · 승

> 5파상승 종결이후 중기하락중 단기반등 / 5파이후 ABC의 B상승판단 / 장기적 상승구간으로 80% 익절후 20% 남겨둠 /
> 장기적인 차트기준 컵엔핸들의 손잡이의 손가락이다 이제 올라간다

| 층 | 값 | 등급 |
|---|---|---|
| L0 | **상승추세** ("장기적 상승구간") | — |
| L1 | `조정 B파 반등` (중기 하락 속) | C |
| L2 | 단기 반등 — 트리거 명시 없음 | — |
| L3 | `장기 패턴(컵앤핸들)` 손잡이 | C |
| L4 | 손절 79,410 · TP1 80,540 (80%) · TP2 84,180 (20%) · 진입 79,682.9 | A |

판정: 유일하게 L4 까지 갖춘 거래 — **템플릿의 기준 사례**. 복기("B파 상승이 강하지 못함, 하단 추세선에서
시간조정, 전고 미돌파 → C 진행 판단, 스위칭")가 다음 거래의 L2 가 됐다. 비고: 1차 익절 후 관망, 84,180 에서 추가 익절.

### 6.4 260905_108$ #2 · 숏 BTC · 9/6 04:23 → 보유중

> B파상승 종결판단 / 이전 고점을 빠르게 돌파해야하는데 돌파하지못함 / ETH 차트와 비교했을때 저항부근이라 돌파 실패판단

| 층 | 값 | 등급 |
|---|---|---|
| L0 | **상승추세** (직전 거래와 같은 판단) → 숏 = **역추세** | — |
| L1 | `B파 종결 → C파` | C |
| L2 | 직전 고점 돌파 실패 | **A** |
| L3 | ETH 저항 대조 | B |
| L4 | 손절 **없음** · TP1 79,590 · TP2 78,400 · TP3 77,530 · 진입 79,885.4 | 절반 |

판정: 트리거는 네 건 중 가장 기계적이다. 그러나 손절이 없어 `/order` 게이트였다면 나가지 못했을 주문이고,
장기 상승 판단 속 숏이라 역추세 표식이 붙는다. 비고에 "이전 저점에서 장기적으로 가져가도 됐을 텐데"라는
후회가 적혀 있다 — L0 와 방향이 어긋난 거래의 전형.

### 6.5 근거 없는 손실 2건 · 100$ TEST #2 (환희) · #5 (후회)

근거 칸이 비어 있고 복기만 있다 — "수익후 환희에 의한 매매", "욕심에 의한 추격진입". 층 구조에 들어갈
내용이 없다. 이 두 건이 `/order` 게이트와 대시보드 경보(REQ-0037·0038)의 존재 이유이며, 자동매매가
없애야 할 거래다. 원칙 층(감정·행동)으로 분류하고 근거 통계에서는 뺀다.

## 7. 자동매매 승격 기준 (정리 기준)

근거 하나가 자동매매 규칙이 되려면 아래를 **전부** 통과한다. 하나라도 빠지면 후보로만 둔다.

| # | 기준 | 어디서 확인 |
|---|---|---|
| 1 | 5층 완비 — L0 칸 · L1 칩 · L2 트리거 한 줄 · L4 손절과 TP 숫자 | `/order` 게이트가 강제 |
| 2 | L2 트리거 등급 A — 가격·시각·봉 수로 적혀 있다 | §5 표 |
| 3 | L0 방향 일치 — 역추세 아님 (1단계) | `/trades` 추세 칩 vs 방향 |
| 4 | 같은 (L0 × L1) 묶음이 30건 이상(`RELIABLE_SAMPLE`), 기대치 > 0, 켈리 > 0 | `/review` 장기추세별·기준별 표 |
| 5 | 규칙을 **사전 등록**하고 신규 데이터로 검증 (REQ-0027·0028 방식) | 백로그 spike |

현재 통과 0건. 가장 가까운 후보 둘:

- `상승추세 × 조정 B파 반등 롱` — 260905 #1. L2 트리거만 정의하면 1~3 통과. 표본 1건.
- `B파 종결 → C파 숏` — 260905 #2. L2 가 A 등급이지만 역추세라 1단계 제외. 기간조정·하락추세에서 같은 트리거가 나오면 후보.

## 8. 앱에서 적는 법 (운영 규칙)

- `/order`: 장기추세 칩 → 기준 칩 → 근거 → 손절·TP. 추세·기준·근거 20자·손절·목표·투입이 다 있어야 열린다.
- 근거 칸 형식 — **첫 줄 = 트리거(L2)**, 둘째 줄부터 보조(L3), 마지막 줄 = 틀렸다고 볼 조건(무효화 시나리오).
  이 순서로 적으면 첫 줄만 뽑아 §5 표와 대조할 수 있다.
- 기록/수정 폼: 동기화로 들어온 거래도 추세·기준을 채운다. 30일이 지난 빈칸은 "복기 대기" 필터에서 본다.
- `/review` 장기추세별 표: 역추세 묶음의 손익이 따로 보인다. `(미기재)` 행이 줄어드는 것이 진척이다.

2. 진입마다 층을 채우고 30건이 쌓이면 §7 4번을 `/review` 에서 읽는다.
