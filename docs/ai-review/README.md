# AI 분석 — 회차 생성 절차 (정본)

화면은 `/ai-review`, 저장은 `ai_reviews` 표, 형식은 `src/lib/ai-review.ts`, 도구는 `scripts/ai-review.mjs`.
**사용자가 대화로 지시할 때만 만든다.** 자동 실행·예약·앱 버튼은 두지 않는다(REQ-0088 사용자 결정).

## 0. 이 분석이 답하려는 것

> 지금 나는 어떤 상태이고, 무엇이 문제이며, 무엇을 교정해야 하고, 무엇을 못 보고 있나.

여러 관점(기준 대조 · 기술 · 기본 · 심리)으로 나누되, 모든 주장은 **이 북의 기록**에서 나와야 한다.
일반론("손절을 잘 지키세요")과 위로는 쓰지 않는다 — 그 북의 거래 번호를 댈 수 없는 문장은 뺀다.

## 1. 순서

1. **이전 회차부터** — `npm run ai-review -- list <북>`. 직전 회차 `nextChecks` 를 이번 회차에서 먼저 점검하고
   결과를 `status` 섹션에 적는다.
2. **재료 뽑기** — `npm run ai-review -- dump <북> <스크래치패드>/dump.json`
   (거래 전 칸 · 체결 · 추가 기록 · 원칙/체크 · 무포지션 · 입출금 · 잔액 스냅샷 · 이전 회차).
3. **지표 재계산** — 앱과 같은 숫자를 써야 화면들과 어긋나지 않는다. `src/lib/` 아래 임시
   `*.test.ts` 하나로 `deriveTrades` · `computeMetrics` · `groupPerformance` 를 dump 에 돌려 결과를 스크래치패드에 쓴다
   (끝나면 지운다). 거래마다 최소한 아래를 뽑는다.
   - 진입·청산 시각(KST) · 보유 분 · 레버리지 · 명목가 · 진입 직전 자금 · 순손익 · 가격손익 · 수수료
   - 직전 청산 뒤 간격(`sinceLastExitMs`) · 뇌동매매지수
   - 손절 시 손실 ÷ 자금(계획 손절가, 없으면 거래소 손절가) · 실제 손실 ÷ 자금 · 그 시점 상한(연패 2 → 5%)
   - 근거 5층 칸 · 근거/복기/감정/비고 · 청산 이후 계획
4. **기준 대조 먼저** (`docs/repeatable/README.md` §1·§2·§4) — 크기 10%/5% · 60분 · 복기 세 줄 ·
   손절 물리기 · 2연패 감축 · 사전 등록 판정(T-30)의 발동 여부.
5. **관점별로 본다**
   - 기술: 셋업·트리거·시계열별 성과, 보유 시간, 손익비, 수수료 ÷ 가격손익, 장 국면(OKX 일봉)과 빈도
   - 기본: 근거에 적힌 이벤트·거시 판단과 방향·결과, 펀딩비
   - 심리: 감정 칩, 복기·통찰 글 원문, 손실/이익 직후 행동(간격·크기 변화), 하루 진입 수, 입금 시점
   - 못 본 것: 데이터가 말하는데 복기 글에 한 번도 나오지 않은 패턴
6. **회차 json 작성** → `save … --dry-run` → `save`. 화면에서 확인.

## 2. 형식 (요약 — 정본은 파서)

```
{ title, periodFrom, periodTo, tradeCount,
  content: { headline, state[], scores[{label,value,note?}],
             sections[{ key, items[{ title, body, severity, evidence[{tradeId,label}], action? }] }],
             nextChecks[], limits[] } }
```

- `key`: status · problems · fixes · blindspots · technical · fundamental · psychology · rules (화면 순서 고정)
- `severity`: high · mid · low · info · **good**(지켜야 할 강점 — 문제만 늘어놓으면 무엇을 유지할지 사라진다)
- `evidence.label` 은 `#seq`. 칩은 `/notes?trade=<id>` 로 간다.
- `action` 은 시계만 보면 예/아니오가 나오는 한 문장으로. "조심한다"는 action 이 아니다.

## 3. 규칙

- **숫자는 계산한 것만.** 쓰기 전에 표·스크립트로 다시 센다. 시각은 KST 로 바꿔 쓴다(DB `created_at` 은 UTC).
- **표본을 적는다.** 30건 미만 묶음은 결론을 내리지 않고 `info` 로만.
- **인과와 상관을 가른다.** 보유 시간·손절 기록 유무처럼 경로 의존인 관계는 본문에 그렇게 적는다.
- **사용자의 말을 근거로 쓸 때는 원문을 인용**하고 거래 번호를 붙인다. 해석은 그 뒤에.
- **한계는 `limits` 에.** 이번 회차가 보지 않은 것(가격 경로, 뉴스 원문 등)을 숨기지 않는다.
- 판정·원칙 변경은 이 분석이 하지 않는다 — 필요하면 `rules` 섹션에서 해당 백로그(REQ)를 가리킨다.
