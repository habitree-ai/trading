# 오답노트 — 판정 기준 정본

과거 거래에서 "다음에 하지 말 것"을 뽑아내는 자리다.
화면은 `/mistakes`, 데이터는 `okx-mistakes.json`, 생성기는 `re_sys/mistakes.mjs`.

**이 문서가 정본이다.** 화면의 설명이 이것과 어긋나면 이 문서가 옳다.

---

## 0. 이 노트가 답하려는 것

> 4,000건 가까이 거래하고 −$42,476 을 잃었다. **다음 주문에서 무엇을 하지 않을 것인가.**

`/diagnosis`(매매 진단)와 겹치지 않는다.

| | 매매 진단 | 오답노트 |
|---|---|---|
| 입력 | 축을 전수로 훑는다(152 검정) | 이름이 이미 붙어 있는 후보 10개 |
| 거르는 법 | FDR · 기간 분할 검증 · 등급 | 비교군과의 거래당 차이 하나 |
| 산출물 | 발견(Finding) | **금지 문장 한 줄** |
| 끝나는 곳 | "무엇이 진짜인가" | `principles.category = 'taboo'` |

진단이 "무엇이 진짜인가"에 답하고 나면, 그 답을 손이 멈추는 문장으로 옮길 자리가
필요하다. 그게 이 화면이고, 그래서 마지막 섹션이 목록이 아니라 편집란이다.

## 1. 파이프라인

```
manual-review.json  (로컬 5.8MB · gitignore · manual-analyze.mjs 산출물)
        │
   mistakes.mjs      (M6)   봇 계정 제외 · 유형별 합계 · 유형별 최악 10건
        ▼
docs/mistakes/okx-mistakes.json   ~55KB · 커밋
        │
   src/lib/mistakes.ts            승률·거래당·차이·t·귀속·판정
        ▼
      /mistakes
```

**집계본에 답을 담지 않는다.** 승률·거래당 손익·비교군과의 차이·유의성·귀속·판정은
전부 앱이 낸다. 문턱을 고치면 `src/lib/mistakes.ts` 한 곳만 바뀌고 과거 회차까지 같은
기준으로 다시 매겨진다.

### 실행

```
node re_sys/mistakes.mjs
```

원장이 갱신되면(`manual-fetch` → `manual-analyze`) 다시 돌린다. 실행하면 건수 대조와
유형별 요약이 콘솔에 찍힌다 — 보유시간 구간의 합이 표본과 어긋나면 거기서 드러난다.

## 3. 유형 정의

`control` 은 **이 유형을 어디서 고를 수 있는가**다. 규칙이 될 수 있는 것은 앞의 둘뿐이다.

### 진입에서 통제 (`entry`)

| id | 판정 기준 |
|---|---|
| `counter-trend` | 진입 시점 SMA20·SMA50 이 만든 추세와 반대 방향 |
| `chase` | 진입 시점 60봉 범위의 끝(돌파·급등락)에서 그 방향으로 |
| `flip` | 같은 종목 직전 거래와 반대 방향 · 직전 청산 후 10분 이내 |
| `revenge` | 같은 종목 직전 거래가 손실 · 직전 청산 후 30분 이내 |
| `overtrade` | 한국 시간 하루 안에서 6번째부터의 진입 |
| `lever-up` | 같은 종목 직전 거래가 손실 · 이번 레버리지가 그보다 높다 |

**`overtrade` 는 원장의 `과잉거래일(하루 N건)` 태그를 쓰지 않는다.** 그 태그는 그날이
몇 건으로 끝나는지를 6번째 거래 시점에 이미 아는 것처럼 군다 — 미래를 훔쳐본다.
순번(`nthOfDay`)은 진입 순간에 실제로 알 수 있다. (`diagnose.mjs` 규율 3과 같다)

### 청산에서 통제 (`exit`)

| id | 판정 기준 |
|---|---|
| `fast-exit` | 보유 시간 120분 미만 |
| `nostop` | 손절 주문 없음 · 보유 중 증거금 대비 최대 역행 50% 이상 · 강제청산 아님 |

### 결과로 정의됨 (`outcome`)

| id | 판정 기준 |
|---|---|
| `giveback` | 보유 중 최대 평가익 30% 이상 · 그러고도 손실 마감 |
| `liq` | 거래소 강제청산 처리 |

이 둘은 **손실 거래에만 붙는다.** 승률 0% 는 결과가 아니라 정의다. 비교군을 내지 않고
규칙으로도 옮기지 않는다 — 얼마를 잃었는지만 센다.

## 4. 판정

합계 손실로 줄 세우지 않는다. **거래가 많았을 뿐인 유형이 늘 1위가 되기 때문이다.**

```
거래당 차이(gap) = 이 유형의 평균 순손익 − 비교군의 평균 순손익
t                = Welch t (분산이 다른 두 표본의 평균 차이)
귀속              = 건수 × 거래당 차이
```

| 조건 | 판정 |
|---|---|
| `control = outcome` | 결과로 정의됨 — 규칙이 되지 못한다 |
| 표본 < 30건 | 재지 않는다 |
| \|t\| < 2 | **차이 없음** — 합계가 큰 것은 건수가 많아서다 |
| \|t\| ≥ 3 이고 gap < 0 | **오답 확인** — 원칙으로 옮길 수 있다 |
| 2 ≤ \|t\| < 3 이고 gap < 0 | **오답 조짐** — 표본을 더 본다. 옮기지 않는다 |
| gap > 0 | **오답이 아니다** |

**왜 3인가.** 후보가 10개다. 문턱을 2 하나로 두면 열 번 재는 동안 우연히 2 를 넘는
것이 하나쯤 나온다. 조짐(2~3)을 버리지는 않는다 — 지우면 다음 회차에 표본이 쌓였을 때
다시 볼 자리가 없다.

정렬은 **귀속** 순이다. "이 유형을 안 했다면 얼마가 남았을까"에 가장 가까운 값이다.

### 회차 1이 말하는 것

**빠른매매만 진짜다.** 나머지 여섯 통념 — 역추세, 복수매매, 과잉거래, 방향 뒤집기,

**무손절 버티기는 오답이 아니다** — 거래당 +23.13, 이 표본에선 오히려 번 쪽이다.
다만 이 유형의 꼬리가 `liq`(강제청산 119건 −7,600)이고, 둘은 정의상 배타적이다
(`nostop` 은 강제청산을 제외한다). "버텨서 벌었다"의 반대쪽 표본이 따로 세어져 있으므로
이 숫자를 손절을 걸지 않을 근거로 읽으면 안 된다.

## 6. 한계

- **유형끼리 겹친다.** 한 거래가 빠른매매이면서 역추세일 수 있다. 귀속 손실을 다 더하면
  실제 손실보다 커진다.
- **앱의 거래 기록(`/trades`)과 열쇠가 이어져 있지 않다.** `okx_pos_id` 가 채워진 행이
  11개뿐이라 화면의 거래는 원장 쪽 식별자로만 가리킨다.
- **「원칙으로 옮기기」는 소급되지 않는다.** 등록한 뒤 새로 적는 거래부터 체크 대상이고,
  증거는 체크 기록이 아니라 다음 회차 원장의 숫자다.
- 비교군은 "그 유형이 아닌 전부"다. 다른 조건을 맞추지 않은 단순 비교이므로,
  교란 요인을 통제한 결론은 `/diagnosis` 쪽을 본다.

## 7. 원칙과의 연결

확인된 오답은 `/mistakes` 에서 `principles` 표의 `taboo` 묶음으로 옮긴다.
새 표를 만들지 않았다 — 거래마다 지켰는지 남기는 배선(`trade_principle_checks`)이
이미 있고, 오답노트 항목도 그 배선을 그대로 써야 복기에서 어긴 날의 손익이 모인다.

원칙 `detail` 마지막 줄에 `발견 id \`mistake:<유형>\`` 마커가 박힌다. 제목으로 맞추면
문구를 고치는 순간 연결이 끊기는데, 고쳐 쓰라고 폼을 열어 주는 설계다.
