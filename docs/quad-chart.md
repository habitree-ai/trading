# 4분할 차트 — 멀티 타임프레임 + 그리기 동기화

`/quad` 탭이 같은 심볼을 봉 단위 4개(기본 15분·1시간·4시간·일봉)로 나란히 보여주고,
어느 창에서 그리든 네 창 모두에 실시간으로 같은 그림을 그리는 방법을 기록한다.

## 1. 왜 자체 차트인가

TradingView 무료 임베드 위젯(실시간 차트 탭, [tradingview.md](tradingview.md))은
창(iframe)마다 완전히 격리되어 **창 사이 그리기 동기화가 불가능**하다 (본 사이트의
멀티차트 동기화는 유료 기능이고 임베드에는 API가 없다). 반면 앱의 자체 차트 엔진
(lightweight-charts + OKX 시세, "당시 차트"와 같은 계보)은 도형 좌표가
**(시각 초, 가격)** 이라 봉 단위가 달라도 같은 자리를 가리킨다 — 같은 도형 배열을
네 창에 내려보내는 것만으로 동기화가 된다. 사용자 확인을 거쳐 자체 차트를 채택했다.

## 2. 구조

| 파일 | 역할 |
|---|---|
| `src/app/(app)/quad/page.tsx` | 서버 페이지 — 높이 컨테이너, `nowMs()` 전달 |
| `src/app/(app)/quad/quad-chart.tsx` | 공유 상태의 주인 — 심볼·도구·색·도형·초안·선택·되돌리기 |
| `src/app/(app)/quad/quad-pane.tsx` | 창 1개 — 차트 생성, 캔들 로딩, 포인터 처리(좌표 변환) |

재사용하는 기존 모듈 (수정 없음, trade-chart.tsx는 함수 4개 `export`만 추가):

- `chart-annotations.ts` — `AnnotationPrimitive`. **창마다 인스턴스 1개**를 붙이고
  같은 도형 배열을 `setData`로 밀어넣는다. 초안(draft) 객체가 포인터 이동마다 새로
  만들어지므로 네 창의 `requestUpdate`가 함께 돌아 실시간 동기 렌더가 된다.
- `hit-test.ts` / `position-tool.ts` / `annotations.ts` / `annotation-history.ts` —
  전부 순수 계산이라 그대로 공유.
- `trade-chart.tsx`의 `readTheme` / `annotationColors` / `formatTick` / `formatKst` —
  차트 색·KST 축 표기를 당시 차트와 맞춘다.

## 3. 그리기 동기화의 원리와 한계

- 도형은 `ChartPoint { t: 초, p: 가격 }`에 붙는다. 렌더 시 각 창이
  `timeToIndex(t, findNearest=true)`로 **자기 봉 단위에 스냅**해 그린다.
- 그래서 **가격축은 모든 창에서 정확**하고, 시간축은 그 창의 봉 단위로 뭉뚱그려진다:
  - 수평선: 완전 무손상.
  - 텍스트: 상위 봉에서 최대 봉 1개 앞으로 밀려 보일 수 있음.
  - 추세선·박스: 두 점이 상위 봉 하나에 겹치면 폭 0(세로선)으로 퇴화할 수 있음.
  - 손익 툴: 최소 폭(160px)이 보장돼 퇴화하지 않고, 손익비 라벨은 가격만으로 계산돼
    모든 창에서 동일.
- 창의 캔들 범위(220봉) 밖 시각은 좌우 끝 봉에 붙는다 — 15분 창은 약 2.3일치만
  들고 있으므로, 일봉 창에서 먼 과거에 그린 도형은 15분 창 왼쪽 끝에 붙는다.
- 손익 툴은 창을 옮겨 다니며 진입→손절→목표를 찍어도 된다 — 점이 좌표라 이어진다.

## 4. 상태와 저장

- 도형·되돌리기(Ctrl+Z, 50개)·선택은 전부 **화면 메모리에만** 있다. 새로고침하면
  사라진다(사용자 확인을 거친 결정 — 저장이 필요해지면 심볼 단위 테이블을 새로 판다).
- 심볼을 바꾸면 그린 내용을 비운다 — 도형이 그 심볼의 가격 축에 붙어 있기 때문.
- 조작: 그리기 도구는 트레이딩뷰식(클릭·드래그), 도형은 눌러 고르고 끌어 옮기며
  Del 삭제, Esc 해제, Ctrl+Z 되돌리기. 텍스트만 내용 입력창이 뜬다.
- 당시 차트와 달리 라벨 입력·잠금·수치 입력(더블클릭)·측정은 없다 — 이 화면은
  즉석 분석용이고, 남길 기록은 거래 상세의 당시 차트에 남긴다.

## 5. 데이터 갱신

- 창마다 `/api/candles?symbol=&bar=&from=&to=`로 최근 220봉을 받는다.
  `to`는 `floorToBar(now)`로 봉 눈금에 스냅 — 같은 봉 안에서는 같은 URL이라
  서버 Data Cache(OKX fetch 24h)를 탄다.
- `now`는 서버가 내려준 값에서 출발해 1분마다 갱신된다. **봉이 닫힐 때만** URL이
  바뀌어 새 캔들이 온다 — 진행 중인 봉의 틱 단위 갱신은 이 경로(history-candles +
  24h 캐시)로는 불가능하다. 틱 실시간이 필요하면 실시간 차트 탭(TradingView 위젯)을
  쓴다.
- 4개 창 동시 로드 = 창당 3페이지 × 4 = 12요청 — OKX 한도(IP당 20회/2초) 안.
  봉 수를 늘릴 때는 이 한도를 같이 봐야 한다(`PANE_BARS` 주석 참고).

## 6. 유지보수

- 봉 단위 추가/변경: `src/lib/okx.ts`의 `BARS`가 원천 — 창의 선택지는 이를 그대로
  따른다. 기본 4개 구성은 `quad-chart.tsx`의 `DEFAULT_BARS`.
- 도형 종류를 더하면 `domain.ts`(모델) → `chart-annotations.ts`(렌더) →
  `hit-test.ts`(집기) 순으로 번지고, 이 화면은 도구 버튼 한 줄만 는다.
- 당시 차트(trade-chart.tsx)와 그리기 엔진을 공유하므로, 엔진 쪽 수정은 두 화면
  모두에서 확인해야 한다.
